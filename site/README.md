# Toolkit pages: sources

The toolkit's GitHub Pages site is generated by `tools/build_pages.py` from `data/`, `method/`
and `review/examples/`, plus the files in this folder. Don't edit the generated pages: fix the
source and build again.

| File | What it is |
|---|---|
| `home.src.html` | The front door. Its `<style>` is the design system for every page (Trust over IP palette). The build adds the shared navigation and links. |
| `examples/linux-case/findings.json` | Linux case study: findings and themes. **AI draft, not yet reviewed**, and labelled so on every page. |
| `examples/arthur-margaret/` | Arthur and Margaret: the **public version** of a persona-led implementation review. The stack it reviewed is deliberately not named. |
| `manifests/` | "Who did what" steps and the question for some examples. |

## Build and check locally

```bash
pip install -r requirements.txt
python3 tools/build_pages.py          # writes _site/
python3 tools/check_pages.py _site    # links, anchors, titles and language
```

Open `_site/index.html` in a browser.

## Publishing

`.github/workflows/pages.yml` builds and checks the site on every pull request. The built site is
attached to the run as `pages-preview`, so reviewers can download and look at it. On merge to
`main` it deploys to GitHub Pages. This needs a one-time setting by a repository admin:
**Settings → Pages → Build and deployment → Source: GitHub Actions**.

Every example shows its review state (AI draft → checked by a person → independently examined →
decided by the task force). Passing the toolkit's checks means a record is well formed, not that
its findings are right.
